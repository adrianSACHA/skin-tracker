# 03 — Workflow CI (jednostkowe + e2e)

Type: task
Status: resolved
Map: .scratch/e2e-smoke-testy/map.md

## Problem

Testy istnieją tylko lokalnie — nikt ich nie uruchomi przy okazji zmiany, więc
ich wartość jest ograniczona. Dotąd żadne testy (nawet jednostkowe) nie biegły
w CI.

## Do decyzji

- Osobny workflow czy dorzucić krok do `deploy.yml`?
- Czy e2e potrzebują sekretów GitHub Actions?

## Answer

**Decyzja: osobny workflow `.github/workflows/e2e.yml` (nazwa „Testy”),
uruchamiany na `push` do `main`, na każdym PR i ręcznie (`workflow_dispatch`).**

- Kroki: `npm ci` → `npm test` (jednostkowe, szybkie) → `npx playwright install
  --with-deps chromium` → `npm run e2e`.
- **Żadnych sekretów**: backend jest zamockowany, a adres `https://e2e.invalid`
  pochodzi z `e2e/support/constants.js`. (To celowy zysk z decyzji w tickecie 01.)
- `playwright-report/` wgrywany jako artefakt (`if: ${{ !cancelled() }}`), więc
  po czerwonym przebiegu widać trace/zrzuty.
- Osobny workflow, a nie krok w `deploy.yml`, żeby czerwone testy **nie
  blokowały wdrożenia** aplikacji i odwrotnie — deploy zostaje taki, jaki był.

Uwaga do zweryfikowania: workflow nie został jeszcze uruchomiony na GitHubie
(lokalny przebieg jest zielony). Pierwszy push pokaże, czy `--with-deps`
i `node-version: 22` wystarczą na `ubuntu-latest`.
